# Дневник академии

## Назначение

«Дневник академии» — сервис для барбер-академии, который ведёт ученика от заявки до выпуска: модерация заявок, домашние задания с фото, проверка и оценки преподавателя, комментарии к работам, чат команды, уведомления и публичное портфолио учеников.

Решение работает в трёх режимах поверх одного backend:

- **мини-приложение MAX** — основной вход: пользователь открывает дневник из чата с ботом, личность подтверждается подписанными данными запуска MAX;
- **бот MAX** — вход на сайт, модерация и роли (`/admin`), проверка работ (`/teacher`), уведомления и приглашения к отзыву;
- **сайт** — тот же интерфейс в браузере; вход подтверждается в боте MAX.

Для жюри есть **демо-режим**: вход без аккаунта MAX по ролям и панель, которая создаёт события в реальном времени.

## Основной пользовательский сценарий

1. **Ученик** открывает мини-приложение в MAX и заполняет заявку (имя и телефон можно взять из профиля MAX кнопкой «Заполнить из MAX»).
2. **Администратор** видит заявку, назначает преподавателей и одобряет ученика.
3. **Ученик** сдаёт домашнее задание: фото (до пяти) и описание.
4. **Преподаватель** получает уведомление в MAX и в приложении, открывает работу, ставит оценку или отправляет на доработку с замечанием; ученик исправляет и отправляет повторно.
5. Ученик, преподаватели и администрация переписываются в чате ученика и в комментариях к работе.
6. **Администратор** следит за очередью проверки и аналитикой (нагрузка преподавателей, отстающие ученики, активность) и одним нажатием напоминает преподавателю о работах.
7. **Гость** смотрит публичное портфолио — принятые работы учеников.

## Состав и архитектура

```
 MAX (клиент) ──► мини-приложение ──┐
                                    │  HTTPS
 браузер ──────────► сайт ──────────┤
                                    ▼
                          ┌────────────────────┐
                          │ web (nginx)        │  статика React + прокси /api
                          └─────────┬──────────┘
                                    ▼
                          ┌────────────────────┐        ┌──────────────┐
                          │ api (NestJS)       │───────►│ S3-хранилище │  фото работ, аватары, вложения
                          └─────────┬──────────┘        └──────────────┘
                                    │ SQLite (том barber-data)
                          ┌─────────┴──────────┐        ┌──────────────┐
                          │ bot (NestJS)       │◄──────►│ MAX Bot API  │  long polling, сообщения
                          └────────────────────┘        └──────────────┘
```

| Компонент | Технологии | Каталог |
| --- | --- | --- |
| `web` | React 19, TypeScript, Vite 8, Zustand, TanStack Query; nginx | `frontend/` |
| `api` | NestJS 12 (Fastify), Prisma 7, SQLite, sharp | `backend/` (`dist/main.js`) |
| `bot` | тот же образ backend: мессенджер-независимые сценарии и адаптер MAX | `backend/src/messenger/` (`dist/bot-main.js`) |

- Backend разбит на модули по доменам: регистрация, работы, проверка, чат, админка, демо. Бот вызывает те же use cases, что и HTTP API, поэтому права и аудит одинаковы.
- Авторизация: подписанный `initData` мини-приложения MAX (HMAC от токена бота) либо web-сессия сайта; роли проверяет отдельный guard.
- Файлы хранятся в S3-совместимом хранилище (или в томе при `STORAGE_DRIVER=local`) и отдаются только через API с проверкой прав.

### Команды бота

Меню команд бот записывает в MAX при запуске (`PATCH /me/commands`) — оно появляется при вводе `/`. Список один для всех; доступ проверяет каждая команда.

| Команда | Кто | Что делает |
| --- | --- | --- |
| `/start` | все | приветствие, кнопка входа (и «Демо для жюри» при `DEMO_MODE`) |
| `/app` | все | открыть дневник в один тап |
| `/me` | ученик | работы по статусам, средний балл, последний отзыв преподавателя, непрочитанные уведомления |
| `/teacher` | преподаватель | работы на проверке с оценкой и комментарием прямо в чате |
| `/stats` | администратор | сводка академии: заявки, очередь проверки, активность за неделю, отстающие; кнопки «Напомнить» преподавателям |
| `/admin` | администратор | модерация заявок и назначение преподавателей |
| `/id` | все | свой ID в MAX (нужен администратору для назначения преподавателем) |
| `/demo` | все, при `DEMO_MODE` | демо-академия в чате: выбор роли, события эмулятора, выход |
| `/help` | все | команды для роли пользователя |

### Демо в чатовом формате

Если жюри входит в демо из мини-приложения MAX, сервер по подписанному `initData` узнаёт его настоящий MAX ID и связывает его с выбранной демо-ролью (таблица `demo_viewers`). Дальше:

- бот присылает приветствие, а уведомления, которые действия жюри адресуют демо-пользователям, пересылает ему в чат с пометкой «🧪 Демо · уведомление для: …»;
- команды бота (`/stats`, `/teacher`, `/me`) работают от демо-роли, а `/demo` даёт эмулятор событий и смену роли прямо в чате;
- реальным пользователям из демо сообщения не уходят; выход из демо (в приложении или кнопкой в `/demo`) снимает связь.

Подробнее: `PROJECT_CONTEXT.md`, `docs/DECISIONS.md`, `docs/db/schema.dbml`.

## Запуск одной командой

Нужен Docker с Compose v2. Из корня репозитория:

```bash
docker compose up --build
```

Откройте http://localhost:8080 — на экране входа будет блок «Демо-доступ для жюри». Без файла `.env` поднимаются сайт, API и демо-академия; файлы хранятся в томе Docker; бот не запускается, пока не задан `MAX_BOT_TOKEN`.

Для подключения к MAX и S3 скопируйте шаблон и заполните значения:

```bash
cp .env.example .env
```

## Параметры и переменные окружения

Переменные читаются из `.env` в корне или из окружения платформы и передаются в `api` и `bot` (блок `x-app-env` в `docker-compose.yml`).

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `WEB_PORT` | `8080` | Порт сайта на хосте (`127.0.0.1:8080`, если впереди обратный прокси) |
| `MAX_BOT_TOKEN` | — | Токен бота MAX: запуск бота, проверка подписи `initData`, уведомления. Без него бот не стартует |
| `MAX_BOT_USERNAME` | — | Ник бота без `@`: вход на сайт через бота, кнопка «Демо для жюри» |
| `WEB_APP_URL` | — | Публичный HTTPS-адрес сайта: мини-приложение и ссылки на форму отзыва |
| `MAX_WEBAPP_AUTH` | `strict` | `strict` — только подписанный `initData`; `optional` — для локальной разработки в браузере; `off` — без проверки |
| `MAX_API_BASE_URL` | `https://platform-api2.max.ru` | Адрес MAX Bot API; рекомендуется `https://platform-api.max.ru` (см. «Известные ограничения») |
| `STORAGE_DRIVER` | авто | `s3` или `local`; пусто — `s3`, если задан `S3_BUCKET`, иначе `local` |
| `S3_BUCKET`, `S3_REGION`, `S3_ENDPOINT` | —, `ru-central1`, — | Бакет, регион и адрес S3-совместимого хранилища |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | — | Ключи доступа к бакету |
| `S3_FORCE_PATH_STYLE`, `S3_PREFIX` | `false`, — | Path-style адресация; префикс ключей в бакете |
| `DEMO_MODE` | `true` | Демо для жюри: вход по ролям, демо-академия, эмулятор событий. `false` — выключить |
| `DEMO_SNAPSHOT_PATH` | — | Путь внутри контейнера к анонимизированному снимку демо-академии (JSON) |
| `CHAT_ENABLED` | `true` | Чат ученика с командой |
| `MAX_HOMEWORK_UPLOAD_MB` | `450` | Лимит размера одного загружаемого файла, МБ |
| `APP_NOTIFICATIONS_RETENTION_DAYS` | `90` | Срок хранения уведомлений (7–365 дней) |

Секреты (`MAX_BOT_TOKEN`, ключи S3) хранятся только в `.env`; файл исключён из Git.

| Сервис | Порт | Доступ |
| --- | --- | --- |
| `web` | `8080` на хосте → `80` в контейнере | сайт и мини-приложение; прокси `/api` и `/health` в `api` |

## Зависимости

- **Для запуска:** Docker Engine и Docker Compose v2. Образы собираются из `node:22-bookworm-slim` и `nginx`.
- **Для разработки:** Node.js 22 и npm; зависимости ставятся командами `npm --prefix backend install` и `npm --prefix frontend install`.
- **Основные библиотеки:** NestJS, Fastify, Prisma, better-sqlite3, sharp, `@aws-sdk/client-s3` (backend); React, Vite, TanStack Query, Zustand (frontend); Playwright (визуальные тесты).
- **Версии зафиксированы** в `backend/package-lock.json` и `frontend/package-lock.json`; в Docker зависимости ставятся через `npm ci` строго по этим файлам.

### Docker-конфигурация

| Файл | Назначение |
|---|---|
| `backend/Dockerfile` | Образ API и бота (один образ, разные команды запуска) |
| `frontend/Dockerfile` | Сборка React-клиента и nginx со статикой и прокси `/api` |
| `docker-compose.yml` | Запуск `web`, `api` и `bot` одной командой |
| `.dockerignore` | Исключает `node_modules`, `dist`, тесты, документацию, данные и `.env` из контекста сборки |
| `.env.example` | Шаблон переменных без токенов, паролей и ключей |

Сборки многоэтапные: в итоговые образы попадают только собранный код и production-зависимости. Полная сборка без кэша занимает около 1,5 минуты, не считая загрузки базовых образов.

## Внешние сервисы и интеграции

| Сервис | Для чего | Обязателен |
| --- | --- | --- |
| **MAX Bot API** (`platform-api.max.ru`) | бот: long polling, сообщения, кнопки, загрузка фото; уведомления пользователям | для бота и уведомлений |
| **MAX Bridge** (`st.max.ru/js/max-web-app.js`) | мини-приложение: `initData`, системная кнопка «Назад», запрос телефона (`requestContact`), вибрация (`HapticFeedback`), «Поделиться» в чат MAX (`shareMaxContent`), скачивание фото (`downloadFile`), подтверждение закрытия при несохранённых данных | только внутри MAX; вне MAX — браузерные замены |
| **S3-совместимое хранилище** (Timeweb, Yandex Object Storage, MinIO и т.п.) | фото работ, аватары, вложения чата | нет — есть `STORAGE_DRIVER=local` |
| **Google Fonts** | шрифты интерфейса | нет — при недоступности используются системные |

Для мини-приложения MAX нужен публичный HTTPS-адрес (`WEB_APP_URL`), указанный в настройках бота на платформе MAX.

## Работа с данными

- **База данных** — SQLite в томе `barber-data` (`/app/data/barber.db`). Схема создаётся из `backend/prisma/schema.sql` при первом запуске `api`; в существующую базу при старте добавляются только новые таблицы, данные не изменяются.
- **Файлы** — в S3 или в томе (`/app/data/uploads`). В БД хранится ключ объекта; входящие изображения перекодируются в JPEG с удалением метаданных EXIF; файлы отдаются через API после проверки прав.
- **Идентичность** — пользователь MAX связан с внутренним пользователем по `max_user_id`. Веб-сессии и токены входа хранятся только как SHA-256-хэши.
- **Доступ** — ученик видит свои данные, преподаватель — назначенных учеников, администратор — всё; гостю доступны только принятые работы обучающихся учеников, без контактов.
- **Аудит** — модерация, назначения, смены ролей и напоминания записываются в `audit_log`.

## Тестовые данные

- **Демо-академия.** При `DEMO_MODE=true` (по умолчанию) API при первом запуске создаёт демо-академию: администратор, преподаватели, ученики с принятыми работами, работы на проверке и на доработке, комментарии, чат, заявка преподавателя. Фото работ генерируются из пула `backend/assets/demo/`.
- **Снимок.** С `DEMO_SNAPSHOT_PATH` академия создаётся из анонимизированного JSON-снимка; реальные данные в репозиторий не входят.
- **Изоляция.** Демо-пользователи получают служебные ID вне диапазона MAX: бот никогда не пишет им, а события эмулятора не отправляют сообщений в MAX.
- **Пересоздать демо** — сбросить всё, что изменили при проверке:

  ```bash
  docker compose exec api node dist/demo/reset.js
  ```

- **Полностью очистить данные:** `docker compose down -v` (удаляет том с базой и локальными файлами).
- **Автотесты** не трогают рабочие данные: каждый e2e-тест создаёт временную SQLite.

  ```bash
  npm --prefix backend install && npm --prefix frontend install
  npm test               # e2e-тесты backend, включая бота на поддельном MAX Bot API
  npm run visual:test    # скриншоты и поведение клиента (сначала: npx --prefix frontend playwright install chromium)
  ```

## Пошаговый сценарий проверки

1. Выполните `docker compose up --build` и откройте http://localhost:8080.
2. В блоке «Демо-доступ для жюри» нажмите **«Войти как администратор»**.
3. Вкладка «Заявки», блок «Сводка академии» → **«На проверке ›»**: список работ с тем, кто проверяет и сколько ждёт; нажмите «Напомнить».
4. Вернитесь и нажмите **«Вся аналитика ›»**: активность за неделю, нагрузка преподавателей, отстающие ученики.
5. Нажмите круглую кнопку **«Демо»** → **«Новая заявка ученика»**. Заявка появится в «Заявках»; отметьте преподавателей и нажмите «Одобрить».
6. «Демо» → **«Ученик сдаёт работу»**, затем **«Сменить роль»** → **«Войти как преподаватель»**.
7. Вкладка «Проверить» → ученик → работа: поставьте звёзды и нажмите «Принять» либо напишите замечание без оценки — работа уйдёт на доработку.
8. «Демо» → «Сообщение в чат»: на вкладке **«Чаты»** появится счётчик непрочитанного; откройте чат и ответьте.
9. «Сменить роль» → **«Войти как ученик»**: профиль, работы с оценками, чат с командой, «+ ДЗ» для загрузки своего фото.
10. «Сменить роль» → «Выйти из демо» → **«Посмотреть работы как гость»**: публичное портфолио. Кнопка «Поделиться» на портфолио или работе даёт ссылку, которая открывает витрину сразу на этом ученике; в просмотре фото есть «Скачать».
    Внутри MAX (в том числе в демо) переключение вкладок, оценка звёздами, отправка сообщения, итог действий и новые события сопровождаются вибрацией, а при закрытии приложения с несохранённым текстом или загрузкой MAX спрашивает подтверждение.
11. С заполненными `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME` и `WEB_APP_URL` (HTTPS) напишите боту `/start`: придёт приветствие с кнопкой «Демо для жюри», мини-приложение откроется из чата с ботом.
12. Войдите в демо из мини-приложения MAX: бот пришлёт приветствие. Нажмите в приложении «Демо» → «Новая заявка ученика» — в чат придёт «🧪 Демо · уведомление для: … (администратор)». В чате введите `/stats`, затем `/demo` → «Стать: преподаватель» → «📷 Ученик сдаёт работу» → `/teacher` и оцените работу прямо в чате.

## Примеры ожидаемого поведения

| Действие | Ожидаемый результат |
| --- | --- |
| `curl http://localhost:8080/health` | `{"ok":true}` |
| Запрос к API без подписи MAX и без сессии при `MAX_WEBAPP_AUTH=strict` | `401` «Требуется заголовок X-Max-Init-Data…» |
| Админ одобряет демо-заявку | Ученик исчезает из «Заявок» и появляется в «Учениках»; назначенные преподаватели получают уведомление в приложении |
| Преподаватель принимает работу с оценкой | Статус «Проверено», оценка видна ученику; после уроков 5, 10 и 15 создаётся приглашение к отзыву |
| Замечание без оценки | Работа «На доработке», у ученика появляется форма исправления |
| «Напомнить» в списке «На проверке» | Преподаватель получает уведомление в приложении и в MAX; кнопка меняется на «Напомнили ✓» |
| Сообщение ученика в чат | У преподавателя и администратора растёт счётчик на вкладке «Чаты»; после открытия чата он сбрасывается |
| Преподаватель открывает чат чужого ученика | `403` «Нет доступа к чату этого ученика.» |
| `/start` боту | Приветствие; при `DEMO_MODE=true` — кнопка «Демо для жюри» |
| Ввод `/` в чате с ботом | Меню команд: `/app`, `/me`, `/teacher`, `/stats`, `/admin`, `/id`, `/demo`, `/help` |
| `/stats` администратором | Сводка академии и кнопки «🔔 Напомнить: <преподаватель> (N)»; нажатие отправляет преподавателю напоминание |
| Вход в демо из MAX, затем событие эмулятора | В чате с ботом — «🧪 Демо · уведомление для: <кому> (<роль>)» с кнопкой «Открыть демо в приложении»; реальным пользователям — ничего |
| «Поделиться» в MAX | Открывается выбор чата MAX; ссылка `/?guest=1&student=…` ведёт прямо в портфолио без входа |
| «Скачать» фото в MAX | Файл сохраняется клиентом MAX по ссылке с подписью на 5 минут; ссылка действует только для этого файла и пользователя |

## Известные ограничения

- База — SQLite на одном узле: `api` и `bot` работают с одним томом, горизонтальное масштабирование API не предусмотрено. Автоматических бэкапов нет.
- Миграции схемы только добавляющие (новые таблицы); изменение существующих таблиц требует ручной миграции.
- У `platform-api2.max.ru` сертификат российского УЦ, которому Node по умолчанию не доверяет, поэтому рекомендуется `MAX_API_BASE_URL=https://platform-api.max.ru` (или добавьте сертификат через `NODE_EXTRA_CA_CERTS`).
- Первого администратора без демо-режима назначают вручную в базе: `role='admin'` в `users` и строка в `user_roles`.
- Состояние диалогов бота (ввод оценки, комментария) хранится в памяти процесса и сбрасывается при перезапуске `bot`.
- В демо-режиме администратор демо-академии видит всех пользователей экземпляра — включайте `DEMO_MODE` только на демонстрационном стенде.
- Кнопка «Заполнить из MAX» и системная кнопка «Назад» работают только внутри мини-приложения MAX. Вне MAX вибрация идёт через Vibration API (Android-браузеры; в Safari на iOS её нет), «Поделиться» — через системное меню или копирование ссылки.
- К сообщению в чате прикрепляется один файл.

## Остановка и повторный запуск

```bash
docker compose down              # остановить; база и файлы в томе сохраняются
docker compose up -d             # запустить снова в фоне
docker compose up -d --build     # пересобрать после обновления кода
docker compose logs -f api bot   # логи API и бота
docker compose down -v           # остановить и удалить данные (том barber-data)
```
